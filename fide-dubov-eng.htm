About the Dubov System

The Dubov Swiss pairing system (FIDE Handbook C.04.4.1, effective February 2026) is designed to maximise fair opposition by equalising the Average Rating of Opponents (ARO) of all players in each scoregroup.

Key Dubov System Principles:

  • Upfloaters only: Unlike the Dutch system, there are no downfloaters. Scoregroups requiring opponents draw upfloaters from lower scoregroups.
  • ARO Equalization: Players with lower ARO are paired with higher-rated opponents.
  • Subgroups G1 and G2: G1 contains White seekers (sorted by ascending ARO); G2 contains Black seekers (sorted by ascending TPN).
  • Middle-out shifter rule (Art. 4.3.3): When subgroup sizes must be equalized, candidates are shifted from the middle of the spectrum outwards.
  • Strict Color Rules ([C3]): Two players with the same absolute color preference can never meet.
  • Application tie-breaks: This tournament configuration ranks players by Points, Buchholz Cut 1, Sonneborn-Berger, Buchholz and TPN. The selected tie-break order is a tournament regulation, not part of the Dubov pairing procedure itself.

Autosave & Backups: Settings and tournament data autosave continuously to browser storage (localStorage). To run separate tournaments simultaneously without overwriting data, use different browsers (e.g., Chrome and Edge). Save a JSON backup after each round. To correct a previously entered result, restore the backup from that round and re-enter the results. Alternatively, edit the JSON file to correct the result.

Registration: Once Round 1 pairings are generated, registration closes permanently (no new players may be added) and tournament settings lock. Between rounds, players can be withdrawn, reinstated, or assigned unplayed rounds (zero or draw value). To correct a player's name, rating, title, or a previously entered result, save the tournament as JSON, edit the file, and reload it via Open tournament.

Importing Player Lists: Player lists can be imported via file (.txt, .csv, .trf) or pasted directly. Lines starting with # or //, as well as blank lines, are ignored.

1. Delimited Text: Fields are separated by semicolons (;), tabs (\t), or commas (,).
Rating: 0–9999 (defaults to 1500 if omitted).
Title: Optional (GM, IM, WGM, FM, WIM, CM, WFM, WCM, or blank).

Names with commas can be entered in three ways:
• Quoted CSV: "Carlsen, Magnus", 2832, GM
• Four unquoted comma-separated fields: Carlsen, Magnus, 2832, GM
• Semicolon or tab-separated: Carlsen, Magnus; 2832; GM

2. TRF Import: Standard FIDE TRF06 / TRF16 / TRF26 files can be opened via Open tournament (or imported/pasted) to load the full tournament—including tournament name, round count (XXR), initial color (XXC), player TPNs, ratings, titles, and complete round-by-round pairings, results, forfeits, and byes. Registration-only 001 lines without round history are also supported.

Pairing Search & Export: Pairings are calculated in a background Web Worker with a strict timeout setting. The maximum number of simulator rounds is 30, but the simulator will stop early if the pairing engine can no longer find a legal round under FIDE rules. Once all tournament rounds have been completed, the Save TRF File button becomes available. Before final submission, the tournament director must enter each player's FIDE ID, date of birth, and federation code. If this information has not been added using the Complete/Edit TRF button, the exported TRF file will contain only the player names, tournament name, and tournament results. All other required fields will be marked with placeholders and can be easily replaced in a text editor.

Baku Acceleration: Optional Baku Acceleration (FIDE Handbook C.04.7, effective February 2026) can be enabled by setting Baku acceleration to On (default Off). Before Round 1, players are split into an upper group GA (the top half, rounded up to the nearest even number) and a lower group GB. During the first half of the tournament (rounded up), players in GA receive virtual points equal to a win in the first half of the accelerated rounds (rounded up) and half a win in the remaining accelerated rounds. This reduces one-sided early-round mismatches in tournaments with wide rating spreads. Virtual points affect only pairing scores and board order, never actual standings, tie-breaks, or TRF exports. Per FIDE rules, Baku acceleration is only available when a win equals two draws and a loss is zero (disabled for 3 / 1 / 0 scoring).

This application does not support late entries or adjourned games. Optional Baku acceleration (FIDE C.04.7, excluding late entries) is supported. The built-in tests are developer regression tests, not the official FIDE endorsement suite.
